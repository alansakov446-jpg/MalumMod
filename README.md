# Ириска — бот-помощник по Iris | Чат-менеджер

Telegram-бот отвечает на вопросы о командах Iris (`@iris_cm_bot`) с помощью Groq и локальной базы знаний `knowledge_base.md`. При исчерпании лимита он последовательно переключает модель на более лёгкую, а затем пробует следующий API-ключ.

## Как пользоваться

- **В группе:** `!ириска помоги замутить человека на 7 дней` (также работают `ириска, ...`, `.ириска ...` и `/ириска ...`). Бот отвечает только на обращения с приставкой.
- **В личке:** можно написать вопрос без приставки.
- **Инлайн:** включите режим через `@BotFather` → `/setinline`, затем в любом чате напишите `@имя_вашего_бота ириска как заключить брак?`. В результатах будут варианты **«Ответ Ириски»** и, если бот нашёл команду в ответе, **«Команда: …»**. Нажатие на второй вариант покажет её для копирования, но не отправит голую команду — так Iris случайно не выполнит её сразу. Кнопка «Спросить Ириску ещё» запускает следующий вопрос.

Для инлайн-вызова слово «ириска» необязательно: после `@имя_вашего_бота` можно сразу написать вопрос.

## Каскад моделей и ключей Groq

### Модели по приоритету

Переменная `GROQ_MODELS` — необязательный *список model ID в порядке приоритета*: сначала более сильная модель, затем резервные. Например:

```text
qwen/qwen3.8-27b,openai/gpt-oss-20b
```

Если `GROQ_MODELS` не задана, бот использует этот каскад автоматически. Старую переменную `GROQ_MODEL` он тоже понимает: указанная модель становится первой, а резервные модели добавляются следом. Проверьте активные ID и доступность моделей для вашего аккаунта в [Groq Console](https://console.groq.com/docs/models): список моделей меняется.

> Важно: прежняя модель по умолчанию `qwen/qwen3.6-27b` была выведена из эксплуатации 14 сентября 2026 года; рекомендованная замена — `qwen/qwen3.8-27b`. Это, вероятно, и объясняет, почему бот перестал получать ответы. Подробности — в [официальной истории депрекаций Groq](https://console.groq.com/docs/deprecations).

Поведение при запросе:

1. Бот отправляет запрос основной модели на текущий ключ.
2. При `429` помечает лимит отдельно для этой пары «ключ + модель», учитывает `Retry-After`/reset-заголовки Groq и пробует следующую модель **на том же ключе**.
3. Пока лимит не сбросился, следующие вопросы пропускают эту модель и сразу используют следующий уровень каскада.
4. Если все модели на ключе недоступны, бот переходит к следующему ключу. Невалидный ключ (`401` или общий `403`) пропускается до перезапуска; `403` именно на доступ к модели переводит запрос на резервную модель. Выведенная из эксплуатации модель пропускается до конца текущего процесса.

По умолчанию при `429` без заголовка сброса действует короткая пауза 60 секунд. Её можно изменить переменной `GROQ_RATE_LIMIT_COOLDOWN_SEC`.

### API-ключи

`GROQ_API_KEY` принимает несколько ключей через запятую, точку с запятой или с новой строки:

```text
gsk_первый,gsk_второй,gsk_третий
```

Не публикуйте ключи и храните их в GitHub Secrets. Учтите, что Groq применяет лимиты на уровне организации: несколько ключей одной организации **не умножают квоту**. Ротация всё равно полезна при разных организациях и для перехода между ключами с разными ошибками доступа; переключение модели помогает, когда лимит относится к конкретной модели. Подробнее: [лимиты Groq](https://console.groq.com/docs/rate-limits).

## Установка на GitHub Actions

1. Добавьте файлы проекта в репозиторий, сохранив `.github/workflows/bot.yml`.
2. В **Settings → Secrets and variables → Actions → Secrets** добавьте:
   - `BOT_TOKEN` — токен Telegram-бота от `@BotFather`;
   - `GROQ_API_KEY` — один или несколько API-ключей Groq.
3. Необязательно: в **Settings → Secrets and variables → Actions → Variables** создайте `GROQ_MODELS`, например `qwen/qwen3.8-27b,openai/gpt-oss-20b`. Переменная необязательна — каскад по умолчанию уже задан. Можно также задать `GROQ_RATE_LIMIT_COOLDOWN_SEC`, `GROQ_REQUEST_TIMEOUT_SEC`, `AI_TOTAL_TIMEOUT_SEC` и `INLINE_AI_TIMEOUT_SEC` в `.github/workflows/bot.yml` или Variables.
4. В `@BotFather` выполните `/setinline` и задайте короткую подсказку, например `спросить Ириску о команде Iris`.
5. Откройте **Actions → Ириска бот → Run workflow** для первого запуска. Затем workflow запускается автоматически каждые 6 часов; один процесс работает около 5 ч 50 мин.

`GROQ_MODEL` поддерживается для старой настройки. Если переменная задана, она становится основной моделью, после неё бот попробует актуальные резервные модели по умолчанию.

## Что внутри

- Вопросы по базе знаний ищутся по подходящим разделам; вся база целиком не отправляется в API.
- История диалога хранится в памяти процесса (отдельно для чатов и инлайн-личного контекста), до 3 пар «вопрос–ответ».
- Точные повторные вопросы инлайн-режима кэшируются локально на короткое время, чтобы не тратить лишние запросы.
- Для API и Telegram заданы таймауты; ответы ограничиваются допустимой длиной сообщения.
- Состояние лимитов/недоступных моделей, история и локальный кэш сбрасываются при перезапуске процесса.

### Переменные окружения

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | Обязательно: токен Telegram-бота |
| `GROQ_API_KEY` | Обязательно: один или несколько API-ключей Groq |
| `GROQ_MODELS` | Необязательно: каскад моделей через запятую, от основной к резервным |
| `GROQ_MODEL` | Старый одиночный параметр, поддерживается для совместимости |
| `GROQ_RATE_LIMIT_COOLDOWN_SEC` | Пауза при `429`, если API не сообщил время сброса; по умолчанию `60` |
| `GROQ_REQUEST_TIMEOUT_SEC` | Таймаут одного HTTP-запроса к Groq; по умолчанию `30` |
| `AI_TOTAL_TIMEOUT_SEC` | Общий таймаут ответа в обычном чате; по умолчанию `60` |
| `INLINE_AI_TIMEOUT_SEC` | Таймаут ответа в инлайн-режиме; по умолчанию `22` секунд |
| `MAX_RUNTIME_SEC` | Через сколько секунд процесс завершится; `0` — без лимита |
